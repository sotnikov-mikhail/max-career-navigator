## 0. Что даёт 0 баллов («Допуск», стр. 11)

Решение не оценивается, если есть хотя бы одна из трёх проблем:

- ☐ **Тема.** Жюри должно увидеть связь с госсервисами. Трек называется «получать госуслуги,
  узнавать о мерах поддержки», а мы формулируем задачу как «карьерный профиль». Поэтому
  в презентации и в README прямо проговорить: профиль — это вход в государственный контур
  занятости молодёжи («Работа России», центры занятости, меры поддержки молодых специалистов),
  верификация идёт через ЕСИА, а пользователь получает понятный путь вместо разрозненных анкет.
- ☐ **Бот должен отвечать весь период проверки.** Сейчас он крутится на MacBook, и если ноутбук
  уснёт, мы получаем 0. Нужен VPS или облако с `docker compose up -d` и `restart: unless-stopped`
  (в compose уже есть). Проверить с чужого телефона, что бот отвечает.
- ☐ **Презентация в PDF.** Без неё решение не оценивается.

## 1. Бот в MAX

**Работоспособность — 30 % технической оценки**

- ☐ Пройти сценарий целиком не меньше 5 раз:
  - ветка «Стажировка»;
  - ветка «Работа»;
  - «Работа» с корректировкой ЗП (0–1 год, вилка от 150 000 ₽);
  - каждый из трёх способов верификации, включая «🔄 Другой способ проверки»;
  - кнопка «✏️ Изменить» на нескольких шагах;
  - `/cancel` → `/start`.
- ☐ Проверить **и в мобильном приложении MAX, и в веб-версии** (ограничение 3). Отдельно
  посмотреть, не обрезаются ли кнопки.
- ☐ Кнопка геопозиции работает в обеих версиях. Если в веб-версии её нет, есть запасной путь:
  кнопки городов или ввод текстом.
- ☐ Напоминание через 30 минут приходит на хостинге, а не только локально.

**Стабильность — 10 %**

- ☐ На произвольный текст, старые кнопки или стикер вместо ответа бот не падает и
  переспрашивает.
- ☐ После перезапуска контейнера пользователь продолжает анкету с того же места: сессии лежат
  в `data/`, volume смонтирован.
- ☐ Посмотреть логи за день работы: не должно быть ошибок 429/400 при удалении сообщений.

**UX — 20 % продуктовой оценки**

- ☐ Нет тупиков. У каждого шага есть понятное действие.
- ☐ Интерфейс сообщает о загрузке («⏳ Проверяем…»), о результате («✅ Верификация…») и
  об ошибке (подсказка формата).
- ☐ Ник бота изменить нельзя (ограничение 11): в материалах везде указывать
  `@t608_hakaton_max_bot`.

**Платформенный бонус +0,15**

Бонус начисляется целиком и только за возможность MAX сверх минимума, которая даёт
пользователю ценность.

- ☐ У нас уже есть **запрос геопозиции** для определения города. Описать это в README и
  в презентации как фичу MAX, а не как мелочь.
- ☐ Можно добавить (на согласование): кнопку **«Поделиться контактом»** на шаге связи
  с экспертами или **мини-приложение с карточкой профиля**. Делать только если успеваем
  без риска для основного сценария.

**Персональные данные — вопрос с высоким риском (стр. 8, п. 05, 152-ФЗ)**

- ☐ Бот просит фото паспорта. В README и на слайде явно указать:
  - данные **не сохраняются** (в submissions пишется только флаг `passportProvided`);
  - проверяется только формат;
  - проверяющим предлагаем **тестовые данные** (шаблон ниже).
- ☐ Положить в README готовый тестовый паспорт текстом и тестовые ИНН и СНИЛС с корректной
  контрольной суммой, чтобы жюри не вводило свои данные.
