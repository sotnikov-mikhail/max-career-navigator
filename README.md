# Твой карьерный навигатор — бот для MAX

Хакатон Минобрнауки России × MAX, трек **«Забота о людях»**.

**Бот:** [@t608_hakaton_max_bot](https://max.ru/t608_hakaton_max_bot) — открыть в MAX (мобильное
приложение или веб-версия) и нажать «Начать». Маршрут проверки — п. 10, тестовые данные — п. 3.2.

## 1. Назначение

Чат-бот в мессенджере MAX, который помогает **студентам колледжей и вузов и недавним
выпускникам**, впервые ищущим стажировку или работу, за пару минут собрать
структурированный и подтверждённый цифровой карьерный профиль вместо заполнения
множества разрозненных анкет. Если ожидания по зарплате заметно выше того, что обычно
предлагают на старте без опыта, бот мягко предлагает их скорректировать.

## 2. Основной пользовательский сценарий

Сценарий разработан командой (15 разделов диалога).

1. Приветствие и имя (свободный ввод).
2. Вопросы кнопками: этап обучения → цель (стажировка / работа) → город (кнопка,
   геопозиция или текст) → сфера (10 направлений) → опыт → сколько часов в неделю готов(а) уделять → оплата →
   «⚡ 50% пройдено» с кнопкой «Продолжить» (сообщение удаляется по нажатию) → формат работы → переезд → переработки → мотивация
   (ровно два варианта, отмечаются ✅, после второго анкета идёт дальше сама).
   Ветки расходятся в двух вопросах:

   | Вопрос | Стажировка | Работа |
   |---|---|---|
   | Опыт | есть / нет | 0–1, 2–3, 4–5, 5+ лет |
   | Оплата | только оплачиваемая / можно без оплаты | 30 000 – 50 000 … от 300 000 ₽ / мес |

3. **Корректировка завышенных ожиданий** (только «Работа»): если опыт 0–1 год или
   1–2 курс, а вилка от 80 000 – 150 000 ₽ и выше, бот предлагает «✏️ Изменить сумму»
   (вилки уже до 150 000 ₽) или «➡️ Оставить сумму». В исходном сценарии условие
   «Опыта нет», но на треке «Работа» такого варианта нет — используется «0–1 год».
   Сообщение корректировки после ответа удаляется; новая сумма обновляет только блок
   с зарплатой в середине анкеты.
4. **Верификация:** Госуслуги (ЕСИА), Банк ID (с выбором банка: Сбер ID, Т-ID, ВТБ ID,
   Альфа ID, Газпромбанк ID) или ручная проверка. Ручная — в два шага
   на одном и том же сообщении: паспорт (быстрее всего — фото разворотов 2–3 и 4–5;
   или все данные текстом по шаблону: серия и номер, кем выдан, дата выдачи, код
   подразделения, дата рождения, место рождения, адрес регистрации — бот называет, чего
   не хватает), затем один документ на выбор — ИНН или СНИЛС, номером или фото. На обоих
   шагах есть «🔄 Другой способ проверки». Строка «✅ Верификация: …» выводится после
   присланных данных, подсказки шагов и «Проверяем…» удаляются. Сообщения пользователя
   с документами бот пытается удалить, но в личном диалоге MAX разрешает удалять только
   свои сообщения (и не чаще двух раз в секунду). Все способы имитируются (см. п. 3).
5. **Связь с экспертами:** онлайн / офлайн, затем финал «🚀 Твой карьерный профиль готов!» с кнопкой
   «Открыть мой профиль» — карточка со всеми ответами и строкой «Ожидай, с тобой свяжутся эксперты
   Федеральной службы по труду и занятости» (эмуляция, см. п. 3); кнопка после нажатия исчезает.
6. **Напоминания:** если человек не дозаполнил анкету — через 30 минут и через 2 часа.
   Вопрос без ответа при этом удаляется из чата, а кнопка в напоминании
   («▶️ Вернуться и догнать остальных» / «▶️ Активировать профиль») задаёт его заново внизу. После финала напоминаний нет.
7. `/cancel` отменяет текущий шаг, `/start` начинает сценарий заново.

**Интерфейс ответов.** Ответ сворачивает вопрос в строку «✅ Вопрос: ответ». Кнопка
«✏️ Изменить» есть только у последнего ответа: нажатие удаляет текущий вопрос,
раскрывает предыдущий обратно в варианты, а после нового ответа текущий вопрос
приходит заново. На последних вопросах (мотивация и далее) «Изменить» нет. Сообщения
об ошибках ввода удаляются, как только пользователь ответил правильно.

## 3. Эмуляция интеграций (важно)

⚠️ **Внешние интеграции в MVP смоделированы** (п. 10 ограничений хакатона). У команды нет
доступа к ЕСИА, Банк ID или API «Работы России», поэтому:

| Что видит пользователь | Как устроено в MVP | Что нужно для реальной интеграции |
|---|---|---|
| Вход через Госуслуги (ЕСИА) | задержка ~1 с и «✅ подтверждено» | регистрация ИС в ЕСИА, OAuth 2.0 / OpenID Connect, соглашение с Минцифры |
| Вход через Банк ID (Сбер ID, Т-ID и др.) | выбор банка + задержка | договор с банком-провайдером ID, OAuth-интеграция |
| Ручная проверка: паспорт + ИНН / СНИЛС | проверка **только формата и полноты** текста, фото принимается без распознавания | сервис проверки документов (СМЭВ), согласие на обработку ПДн, защищённое хранилище |
| Профиль «внесён в систему» | JSON-запись в локальный `data/submissions.json` | API «Работы России» / региональных центров занятости |
| Финал: «рутину по поиску и подбору берут на себя эксперты Федеральной службы по труду и занятости», выбор онлайн / офлайн связи | целевая модель: реального обращения в Роструд нет, выбор формата связи только сохраняется в профиле | соглашение с Рострудом / службой занятости региона о приёме профилей и обратной связи |

В сообщениях бота пометок «демо» нет — пользовательский путь выглядит как в целевом
продукте. Эмуляция задекларирована здесь и в презентации. Это осознанное ограничение
MVP, а не попытка выдать смоделированные данные за реальную интеграцию.

## 3.1. Работа с данными

- **Что хранится.** `data/sessions.json` — прогресс анкеты (ответы и служебное состояние
  диалога, ключ `<user_id>:<chat_id>`); `data/submissions.json` — завершённые профили:
  имя, ответы анкеты, способ верификации и флаги `passportProvided` / `idDocumentProvided`.
- **Что НЕ хранится.** Номера паспорта, ИНН, СНИЛС и фото документов не сохраняются нигде:
  бот проверяет формат в памяти и записывает только факт, что документ предоставлен.
  Сообщения с документами бот пытается удалить из чата (MAX может это запретить — см. п. 2).
- **Где.** Локальные файлы в `./data` (в Docker — смонтированный volume). Каталог в
  `.gitignore`, в репозиторий не попадает.
- **Внешние сервисы.** Только MAX Bot API (`platform-api2.max.ru`). Других сетевых
  обращений нет.
- **Для продакшена** потребуется согласие на обработку ПДн (152-ФЗ), БД вместо файлов
  и хранение в РФ.

## 3.2. Тестовые данные для проверки

Реальные документы вводить не нужно. Для ручной проверки подойдут заведомо тестовые значения:

Паспорт (одним сообщением):

```
Серия и номер: 0000 000000
Кем выдан: ГУ МВД России по тестовой области
Дата выдачи: 01.01.2020
Код подразделения: 000-000
Дата рождения: 01.01.2003
Место рождения: гор. Тестовый
Адрес регистрации: гор. Тестовый, ул. Примерная, д. 1
```

Вместо текста можно прислать две любые картинки (развороты не распознаются).
ИНН: `000000000000` · СНИЛС: `000-000-000 00` (проверяется только формат: 10/12 и 11 цифр).

## 4. Архитектура

```
src/
  bot.ts                    — точка входа: сборка Bot, middleware, запуск polling
  config.ts                 — переменные окружения
  keyboards.ts               — сборка inline-клавиатур MAX
  reminders.ts               — напоминания через 30 минут и 2 часа (фоновая проверка сессий)
  dialog/
    types.ts                 — типы профиля и шагов сценария
    script.ts                 — все тексты и варианты ответов
    flow.ts                    — сценарий (state machine) на ScenarioEngine SDK
  session/
    fileStore.ts               — файловое хранилище сессий (переживает рестарт)
  services/
    verification.ts             — демо-верификация (формат ИНН/СНИЛС + задержка)
    geo.ts                      — город по геопозиции (ближайший из списка, без геокодера)
    profileRegistryMock.ts      — эмуляция передачи профиля во внешний реестр (JSON-файл)
test/
  flow.test.ts                      — unit-тесты сценария без сети
certs/
  russian_trusted_ca_bundle.pem      — CA-бандл для TLS к platform-api2.max.ru (см. п.9)
```

Диалоговая логика построена на встроенном в SDK `@maxhub/max-bot-api` движке
сценариев (`defineScenario`/`ScenarioEngine`) и сессиях (`session()`), а не на
самописном редьюсере — это официальный, задокументированный механизм SDK для
пошаговых сценариев с сохранением прогресса.

## 5. Стек и зависимости

- Node.js 22 LTS (в Docker — `node:22-alpine`), TypeScript (ESM).
- [`@maxhub/max-bot-api`](https://github.com/max-messenger/max-bot-api-client-ts) —
  официальный SDK MAX Bot API (long polling, без публичного HTTPS-эндпоинта).
- `dotenv` — загрузка `.env`.
- Версии зависимостей зафиксированы точно в `package.json` и `package-lock.json`.

## 6. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота MAX (выдаётся организаторами хакатона через Master Bot) |
| `SESSIONS_FILE` | нет | Путь к файлу сессий (по умолчанию `data/sessions.json`) |
| `SUBMISSIONS_FILE` | нет | Путь к файлу демо-заявок (по умолчанию `data/submissions.json`) |

## 6.1. Внешний сервис, который нельзя поднять в Docker

| Сервис | Назначение | Что нужно для проверки |
|---|---|---|
| MAX Bot API (`https://platform-api2.max.ru`) | приём сообщений пользователя (long polling) и отправка ответов бота | токен бота в `BOT_TOKEN` (выдают организаторы); исходящий HTTPS-доступ к `platform-api2.max.ru:443`; CA-бандл Минцифры — уже в репозитории (п. 9) |

Других внешних сервисов, баз данных и сетевых обращений нет: ЕСИА, Банк ID и передача профиля
эмулируются внутри бота (п. 3), данные хранятся в локальных файлах (п. 3.1).

## 7. Порты

Бот работает через **long polling** (исходящие запросы к MAX API), входящий
HTTP-порт не требуется и не открывается ни локально, ни в Docker-конфигурации.

## 8. Запуск

### Через Docker (одна команда)

Предварительно один раз создать `.env` с токеном:

```bash
cp .env.example .env
```

Запуск:

```bash
docker compose up --build
```

Сборка занимает меньше минуты (замер: ~35 с на чистой сборке без кэша, без учёта загрузки
базового образа).

Поднимает единственный сервис `bot`, читает переменные из `.env`, монтирует
`./data` для сохранения сессий/демо-заявок между перезапусками.

> **Один токен — один запущенный экземпляр.** Рабочий бот уже развёрнут на сервере
> команды, и для проверки сценария достаточно открыть его в MAX. При локальном запуске
> с тем же токеном два экземпляра будут забирать одни и те же обновления и отвечать
> через раз — для проверки сборки используйте отдельный токен или предупредите команду.

### Остановка и повторный запуск

```bash
docker compose down      # остановка
docker compose up --build  # повторный запуск (данные в ./data сохраняются)
```

### Локально без Docker

```bash
npm ci
cp .env.example .env   # и заполнить BOT_TOKEN
npm run build
npm start
# или для разработки с автоперезапуском:
npm run dev
```

## 9. Известное техническое ограничение окружения (TLS)

`platform-api2.max.ru` предъявляет сертификат, выпущенный российским
государственным удостоверяющим центром («Russian Trusted Sub CA» / Минцифры
России), который отсутствует в стандартном доверенном наборе сертификатов
Node.js и большинства базовых Docker-образов. Без этого корневого сертификата
TLS-соединение с Bot API MAX завершается ошибкой
`UNABLE_TO_GET_ISSUER_CERT_LOCALLY`.

Решение: в репозиторий включён публичный CA-бандл
`certs/russian_trusted_ca_bundle.pem` (официальные сертификаты Минцифры России,
скачаны с `gu-st.ru`), который подключается через переменную окружения
`NODE_EXTRA_CA_CERTS` — уже прописано в `npm run dev`/`npm start` и в
`Dockerfile`. Дополнительных действий не требуется.

### Ожидаемое поведение при ошибках

- Произвольный текст на этапе выбора варианта — бот просит выбрать вариант кнопкой, сессия не теряется.
- Пустое имя/город — бот просит повторить ввод.
- Сообщения об ошибках ввода удаляются, как только пользователь ответил правильно.
- Некорректный формат ИНН / СНИЛС — бот объясняет требуемый формат и просит повторить.
- Кнопка из старого сообщения, когда анкета уже сброшена, — бот отвечает, что кнопка неактивна, и подсказывает /start.
- Двойное нажатие или кнопка уже отвеченного вопроса — нажатие молча подтверждается и игнорируется.
- Повреждённый файл сессий или заявок не роняет бота при старте; запись файлов атомарная.

## 11. Тесты

```bash
npm test
```

Юнит-тесты (`test/flow.test.ts`) проверяют переходы состояний сценария без
обращения к сети: валидацию ответов, ветки стажировка/работа, проверку
«опыт + оплата», правку старых ответов и смену цели, город по геопозиции,
верификацию, уборку сообщений, напоминания, а также форматы паспорта, ИНН и СНИЛС.

## 12. Потенциал масштабирования

- **Ядро продукта** (не меняется при масштабировании): логика сценария,
  архитектура state machine, модель профиля и механика верификации.
- **Переменная часть**: региональные данные (сейчас — пять городов в списке быстрого
  выбора), реальная интеграция с ЕСИА Госуслуг вместо
  демо-верификации, реальная интеграция с API «Работа России»/Роструда вместо
  `profileRegistryMock`, расширение направлений и формулировок под другие сегменты
  (например, выпускников СПО отдельно от вузов).
- Следующий шаг для пилота: региональный центр занятости молодёжи как первый
  партнёр, передача верифицированных профилей через API «Работы России».

## 13. Известные ограничения MVP

- Верификация и передача анкеты — демо-режим (см. п.3).
- Быстрый выбор города — пять городов; остальные вводятся текстом, геопозиция
  определяет город только в радиусе 150 км от этих пяти.
- Хранилище сессий — локальный JSON-файл (подходит для одного экземпляра бота;
  для горизонтального масштабирования потребуется внешнее хранилище, например
  Redis или БД — сессионный слой SDK это штатно поддерживает через интерфейс
  `SessionStore`).
- Мини-приложение не реализовано — весь сценарий проходит в чате бота.
- Получение обновлений — long polling (для продакшена MAX рекомендует webhook; SDK
  поддерживает его штатно, смена не затрагивает логику сценария).
