# Твой карьерный навигатор — бот для MAX

Хакатон Минобрнауки России × MAX, трек **«Забота о людях»**.

## 1. Назначение

Чат-бот в мессенджере MAX, который помогает **студентам 3–4 курсов вузов/СПО и
выпускникам (до ~1 года после выпуска)**, впервые ищущим стажировку или работу,
за пару минут собрать структурированный цифровой карьерный профиль вместо
заполнения множества разрозненных анкет, и подсказывает, насколько их ожидания
по зарплате реалистичны для выбранного направления и формата занятости.

## 2. Основной пользовательский сценарий

Сценарий — по документу «Твой карьерный навигатор: полный сценарий диалога» (15 разделов).

1. Приветствие и имя (свободный ввод).
2. Вопросы кнопками: этап обучения → цель (стажировка / работа) → город (кнопка,
   геопозиция или текст) → сфера (10 направлений) → опыт → занятость → оплата →
   «⚡ 50% пройдено» с кнопкой «Продолжить» (сообщение удаляется по нажатию) → формат работы → переезд → переработки → мотивация
   (ровно два варианта, отмечаются ✔️, после второго анкета идёт дальше сама).
   Ветки расходятся в двух вопросах:

   | Вопрос | Стажировка | Работа |
   |---|---|---|
   | Опыт | есть / нет | 0–1, 2–3, 4–5, 5+ лет |
   | Оплата | только оплачиваемая / можно без оплаты | 30 000 – 50 000 … от 300 000 ₽ / мес |

3. **Корректировка завышенных ожиданий** (только «Работа»): если опыт 0–1 год или
   1–2 курс, а вилка от 80 000 – 150 000 ₽ и выше, бот предлагает «✏️ Изменить ответ»
   (вилки уже до 150 000 ₽) или «➡️ Оставить как есть». В исходном сценарии условие
   «Опыта нет», но на треке «Работа» такого варианта нет — используется «0–1 год».
4. **Верификация (демо):** Госуслуги (ЕСИА), Банк ID или ручная проверка — паспорт
   (обязательно: фото разворотов 2–3 и 4–5 или серия и номер текстом) и один документ
   на выбор — ИНН или СНИЛС, номером или фото. Все способы имитируются
   (см. п. 3): фото принимается без распознавания, номера и фото не сохраняются —
   в заявку попадает только факт, что документ предоставлен.
5. **Связь с экспертами:** онлайн / офлайн, затем финал «Это твоё начало!» с кнопками
   «Открыть мой профиль» (карточка со всеми ответами) и «Посмотреть предложения».
6. **Напоминания:** если человек не дозаполнил анкету — через 30 минут и через 2 часа.
   Вопрос без ответа при этом удаляется из чата, а кнопка «▶️ Вернуться» задаёт его
   заново внизу. Если анкета заполнена, но подборка не открыта — тоже через 30 минут
   и 2 часа («📋 Открыть подборку»).
7. `/cancel` отменяет текущий шаг, `/start` начинает сценарий заново.

**Интерфейс ответов.** Ответ сворачивает вопрос в строку «✅ Вопрос: ответ». Кнопка
«✏️ Изменить» есть только у последнего ответа: нажатие удаляет текущий вопрос,
раскрывает предыдущий обратно в варианты, а после нового ответа текущий вопрос
приходит заново. На последних вопросах (мотивация и далее) «Изменить» нет. Сообщения
об ошибках ввода удаляются, как только пользователь ответил правильно.

## 3. Ограничения демо-режима (важно)

⚠️ **Верификация через ИНН/ID и «передача анкеты на биржу труда» —
полностью смоделированы.** У команды нет доступа к ЕСИА Госуслуг или к API
Роструда/«Работы России», поэтому:

- верификация через Госуслуги и Банк ID — имитация с задержкой, ручной ввод
  проверяет только формат паспорта (10 цифр), ИНН (10/12) или СНИЛС (11), фото
  принимается без распознавания — никакого реального
  запроса к государственным системам или банкам не происходит;
- «отправка анкеты в биржу труда» — это добавление JSON-записи в локальный
  файл `data/submissions.json`, а не обращение к внешней системе;
- база вакансий (`data/vacancies.json`) — синтетический тестовый набор данных
  (помечен полем `"synthetic": true`), а не реальная база вакансий.

Это осознанное и явно задекларированное ограничение MVP, а не попытка выдать
смоделированные данные за реальную интеграцию.

## 4. Архитектура

```
src/
  bot.ts                    — точка входа: сборка Bot, middleware, запуск polling
  config.ts                 — переменные окружения
  keyboards.ts               — сборка inline-клавиатур MAX
  reminders.ts               — напоминания через 30 минут и 2 часа (фоновая проверка сессий)
  dialog/
    types.ts                 — типы профиля и шагов сценария
    script.ts                 — все тексты и варианты ответов
    flow.ts                    — сценарий (state machine) на ScenarioEngine SDK
  session/
    fileStore.ts               — файловое хранилище сессий (переживает рестарт)
  services/
    verification.ts             — демо-верификация (формат ИНН/СНИЛС + задержка)
    geo.ts                      — город по геопозиции (ближайший из списка, без геокодера)
    matching.ts                   — подбор вакансий из data/vacancies.json
    laborExchangeMock.ts           — демо-запись «в биржу труда»
data/
  vacancies.json                   — синтетический датасет вакансий/стажировок
test/
  flow.test.ts                      — unit-тесты сценария без сети
certs/
  russian_trusted_ca_bundle.pem      — CA-бандл для TLS к platform-api2.max.ru (см. п.9)
```

Диалоговая логика построена на встроенном в SDK `@maxhub/max-bot-api` движке
сценариев (`defineScenario`/`ScenarioEngine`) и сессиях (`session()`), а не на
самописном редьюсере — это официальный, задокументированный механизм SDK для
пошаговых сценариев с сохранением прогресса.

## 5. Стек и зависимости

- Node.js 20+, TypeScript (ESM).
- [`@maxhub/max-bot-api`](https://github.com/max-messenger/max-bot-api-client-ts) —
  официальный SDK MAX Bot API (long polling, без публичного HTTPS-эндпоинта).
- `dotenv` — загрузка `.env`.
- Зависимости и версии зафиксированы в `package.json` / `package-lock.json`.

## 6. Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота MAX (выдаётся организаторами хакатона через Master Bot) |
| `SESSIONS_FILE` | нет | Путь к файлу сессий (по умолчанию `data/sessions.json`) |
| `SUBMISSIONS_FILE` | нет | Путь к файлу демо-заявок (по умолчанию `data/submissions.json`) |
| `VACANCIES_FILE` | нет | Путь к датасету вакансий (по умолчанию `data/vacancies.json`) |

## 7. Порты

Бот работает через **long polling** (исходящие запросы к MAX API), входящий
HTTP-порт не требуется и не открывается ни локально, ни в Docker-конфигурации.

## 8. Запуск

### Через Docker (одна команда)

```bash
docker compose up --build
```

Поднимает единственный сервис `bot`, читает переменные из `.env`, монтирует
`./data` для сохранения сессий/демо-заявок между перезапусками.

### Остановка и повторный запуск

```bash
docker compose down      # остановка
docker compose up --build  # повторный запуск (данные в ./data сохраняются)
```

### Локально без Docker

```bash
npm install
cp .env.example .env   # и заполнить BOT_TOKEN
npm run build
npm start
# или для разработки с автоперезапуском:
npm run dev
```

## 9. Известное техническое ограничение окружения (TLS)

`platform-api2.max.ru` предъявляет сертификат, выпущенный российским
государственным удостоверяющим центром («Russian Trusted Sub CA» / Минцифры
России), который отсутствует в стандартном доверенном наборе сертификатов
Node.js и большинства базовых Docker-образов. Без этого корневого сертификата
TLS-соединение с Bot API MAX завершается ошибкой
`UNABLE_TO_GET_ISSUER_CERT_LOCALLY`.

Решение: в репозиторий включён публичный CA-бандл
`certs/russian_trusted_ca_bundle.pem` (официальные сертификаты Минцифры России,
скачаны с `gu-st.ru`), который подключается через переменную окружения
`NODE_EXTRA_CA_CERTS` — уже прописано в `npm run dev`/`npm start` и в
`Dockerfile`. Дополнительных действий не требуется.

## 10. Пошаговый сценарий проверки

1. Открыть бота в MAX (мобильное приложение или веб-версия) по ссылке/юзернейму,
   выданному организаторами.
2. Отправить `/start` (или просто открыть чат — сценарий запускается автоматически).
3. Ввести имя, пройти все шаги кнопками (город — кнопкой, геопозицией или текстом).
   На любом шаге нажать «✏️ Изменить» у последнего ответа — текущий вопрос исчезает,
   предыдущий раскрывается; после нового ответа вопрос приходит заново.
4. Трек «Работа»: опыт 0–1 год и вилка 150 000 – 300 000 ₽ — после мотивации должен
   появиться блок корректировки; «Изменить ответ» показывает вилки до 150 000 ₽.
5. Верификация: выбрать Госуслуги / Банк ID (демо) или ручную проверку — паспорт
   (фото разворотов 2–3 и 4–5 или 10 цифр), затем ИНН / СНИЛС (номером или фото). Затем выбрать онлайн / офлайн.
6. В финале нажать «Открыть мой профиль» (карточка ответов) и «Посмотреть
   предложения» (демо-вакансии). Проверить новую запись в `data/submissions.json`.
7. Остановиться посреди анкеты на 30 минут — должно прийти напоминание, а вопрос без ответа исчезнуть.
8. Отправить `/cancel` в середине сценария — убедиться, что сценарий
   прерывается корректно, а `/start` запускает его заново.

### Ожидаемое поведение при ошибках

- Нажатие устаревшей/повторной кнопки или отправка произвольного текста на
  этапе выбора варианта — бот переспрашивает тем же вопросом, не роняя сессию.
- Пустое имя/город — бот просит повторить ввод.
- Сообщения об ошибках ввода удаляются, как только пользователь ответил правильно.
- Некорректный формат ИНН / СНИЛС — бот объясняет требуемый формат и просит повторить.
- Кнопка из старого сообщения, когда анкета уже сброшена, — бот отвечает, что кнопка неактивна, и подсказывает /start.

## 11. Тесты

```bash
npm test
```

Юнит-тесты (`test/flow.test.ts`) проверяют переходы состояний сценария без
обращения к сети: валидацию ответов, ветки стажировка/работа, проверку
«опыт + оплата», правку старых ответов и смену цели, город по геопозиции,
переход к верификации/предложениям, а также формат ИНН и подбор вакансий.

## 12. Потенциал масштабирования

- **Ядро продукта** (не меняется при масштабировании): логика сценария,
  архитектура state machine, модель профиля, механика подбора и демо-верификации.
- **Переменная часть**: региональные данные (сейчас — несколько городов РФ в
  синтетическом датасете), реальная интеграция с ЕСИА Госуслуг вместо
  демо-верификации, реальная интеграция с API «Работа России»/Роструда вместо
  `laborExchangeMock`, расширение направлений и формулировок под другие сегменты
  (например, выпускников СПО отдельно от вузов).
- Следующий шаг для пилота: региональный центр занятости молодёжи как первый
  партнёр, подключение реального API вакансий взамен `data/vacancies.json`.

## 13. Известные ограничения MVP

- Верификация и передача анкеты — демо-режим (см. п.3).
- Датасет вакансий — синтетический, ограничен несколькими городами и направлениями.
- Хранилище сессий — локальный JSON-файл (подходит для одного экземпляра бота;
  для горизонтального масштабирования потребуется внешнее хранилище, например
  Redis или БД — сессионный слой SDK это штатно поддерживает через интерфейс
  `SessionStore`).
- Мини-приложение не реализовано — весь сценарий проходит в чате бота.
